## 1. 本轮到底交付什么

本文是 [v2工程合同](agency-ideal-lab-execution-plan-v2-2026-09-08.md) 的补充，不另建实验架构或第三套 runner。原文第0节的规范优先级、G01–G14、W00–W10、P01–P18、全部场景、重复次数与质量阈值继续有效。本文细化本次审计缺口和执行终点；不得以本文未重复列出某项为由删减原要求。

本轮执行目标是：补齐实验实现，完成真实 API 的完整实验及修复迭代，最后给出可复核的效果结论。不是“完成实验基础设施后再等下一轮任务”。实验通过与生产通过仍须区分；本任务不包含生产接入或部署。

必须区分三个结果：

- **验证完成且达标**：所有规定证据齐全，全部阈值满足，结论为 passed_experiment。
- **验证完成但不达标**：全部规定测试与评审已执行，仍有失败，结论为 failed，并列出未解决问题。不得称效果已实现。
- **验证未完成**：有必测项缺证据，completion=incomplete；另列已知失败。存在已知失败时总体仍为 failed，不能用 inconclusive 掩盖失败；无已知失败但证据不足才为 inconclusive。

“一次完成”指同一个交接任务中完成开发、测试、迭代、回归和最终复核，可以有多个不可变 run；不指只调用一次 API、不发生修复、保证模型一定达标。源访问、环境权限、服务可用性、费用和人审输入可能构成外部阻塞，必须提前查明，不能承诺客观上不存在的无条件通过。

## 5. 补齐工单及完成证据

### C01：完整资源可用性及真实隔离

归属：controller/export/evaluation；对应W01–W03。

1. 完成源身份核验和授权范围记录，敏感凭据不写报告。导出用一致性快照，逐字段/资源核对，涵盖原资源范围、WAL与分页完整性。
2. controller启动真正受限worker，模型密钥只在独立gateway。worker禁止生产读写与oracle访问；出网仅通过受控gateway。
3. 由实际worker及其子进程尝试文件读写、直接socket/HTTP和oracle访问，用OS层结果证明拒绝；正常快照读取和合法gateway访问为正对照。调用自定义check函数抛异常不够。
4. hash报告明确覆盖清单。生产文件/依赖hash、数据逻辑快照、外部访问/投递证据分别列出；不能由几个源码hash不变推断Bot与DB绝无副作用。线上自然变化不能伪装为实验污染，应凭审计记录归因。

完成：E0/E1证据合格，失败探针实际被拒绝，正对照实际成功；源不明则维持阻塞。

### C02：模型真正消费通过对账的副本

归属：cli/context/adapters/export；对应W04。

1. 正式FROZEN运行只接受run manifest绑定的快照及账号映射；public_state只能用于明确标注的确定性单元合同，不进入真实场景主组。
2. 从快照构建三层上下文和可发现目录，包含有效人格/长期追求、企业档案、当前关系/日程/任务、历史及资源索引；保留来源、时间与认知状态。不得用泛化“合作伙伴”一句替换原完整角色设定。
3. 每次真实模型调用保存实际合成prompt及资源引用/hash。工具记录同一快照版本、owner、实际检索参数、结果来源。
4. 集成反例：复制独立快照，仅修改一项企业背景/指定日期数值，重新绑定独立oracle。正式context/adapter路径必须反映变化；旧版本结果不得混入。另做缺档案、跨账号、旧数据分支。不能只测试JSON读取函数。
5. 保持按需检索，不把全库塞进prompt。验证资料“可发现、可查询、实际被选用”三个层次，不强制每个事件读取所有资源。

### C03：工具完成真实隔离状态变更

归属：adapters/store/loop/policy/transport；对应W04–W05。

完成：用查询与重启结果证明状态变化，并提交“未知→询问→回答→判断变化→确认/拒绝→再次复用”的真实多轮API轨迹。只有返回complete不算完成。

## 6. 开发—测试迭代顺序

1. C00前置核验；同时完成C01–C06中不依赖外部输入的开发。
2. 完成组件合同、真实快照集成、验收器变异检查。已知工程缺陷先修，不浪费API验证占位实现。
3. 冻结版本与oracle；E0/E1/E2合格后运行E3。保留真实原始调用，先排环境错误，再判断行为。
4. 按最早偏差归因：源/导出→可发现上下文→模型选择→工具执行→状态→投递。工程故障用确定性反例修；只有上下文及执行正确而选择/表达不佳时，才做固定条件的prompt配对试验。模型差异单列，不用换模型掩盖工程缺陷。
5. 修复后按原要求失败场景至少5次及邻近工作/个人回归，随后完整固定套件。冻结候选后才启用留出，不拿留出反复调prompt；若已泄漏用于修复，记录并准备独立新留出，旧失败保留。
6. 完成第二模型、图片、连续性、性能、人审、最终边缘检查。任何版本变化据影响重跑，不混合多个版本的最好成绩。
7. 原门槛保持：每模型固定每族≥4/5；某族一次重复必须全部强制分支合格才算该重复合格，不能改成分别按分支平均。整体及分域≥90%，维度≥3、硬失败为0；其他专门指标继续按原文。质量不足须继续授权预算内修复，不能以“API能调用”结案。

不新增当轮多级LLM审稿。验收器在离线观察效果，不替模型回答。完整实验可能发现设计仍不达标，这是有效结论；执行者不能为了凑通过改欲、删个人分支、用固定答案或放松标准。

## 7. 什么可以停，什么不能停

以下不是终点：CLI能启动、W00完成、E0对账、E2几个断言通过、冒烟能返回、已产出一张报告、首轮出现模型质量失败。

真实阻塞仅包括已查证且当前无法解决的外部条件，如只读源不可访问、所需环境权限缺失、provider持续不可用/额度不足、预算用尽或必须的人审输入未到。必须列出：尝试及错误证据、准确缺项、被挡的阶段、已完成独立工单、用户/维护者所需最小操作、解除后的下一步。不得要求用户重新授权已授权的普通API测试。

临时断网可有限重试并落checkpoint；预算内可修工程问题继续修复。若需要变更已批准的目标架构才能继续，提交具体差异，不能静默推翻。人审未到时先完成全部可自动完成的阶段，并交付可直接评审的材料；整体仍标未完成。

## 8. 最终交付清单与复核

- `completion-preflight.json`：源、隔离、provider、费用、人审就绪事实。
- `execution-manifest.json`：全场景分母、次数、模型、路径、实际证据；没有planned占位。
- `mutation-coverage.json`：M/X正式路径正负对照及保护失效时测试失败的证据。
- `context-consumption.json`：源到模型实际请求的绑定；导出和消费没有两套数据。
- `state-roundtrip.json`：任务/知识/反馈/重启/权限变更的持久化与真实多轮复用。
- 原规范全套manifest、原始API响应、trace、工具记录、资产、回执、scores、成本、盲评包和edge-check报告。
