# 西宇理想链路实验规范与执行交接

日期：2026-09-08。状态：设计已落文档，实验系统尚未搭建，未宣称通过。

## 0. 执行任务与适用范围

任务：在完全隔离的实验系统中复刻当前授权用户所能使用的信息、角色状态与相关能力，以真实模型API完成“人格与长期追求参与理解 → 动念 → 策略与媒介 → 查询/准备/表达 → 投递到测试接收器 → 用户反馈 → 持续推进”的多轮实验。执行同事负责实现与证据采集，交回原评审者和用户判断效果。

本规范定义理想目标实现，不要求复刻当前生产的错误编排。临时独立系统是用户明确授权的实验范围，不接管生产、不增加生产调度器、不部署。现有生产功能迁移须另行制定集成方案。

“完全模拟”指信息、能力、状态、时序与结果契约可证明等价；不能承诺随机模型输出、未来用户行为、未来外部数据与真实微信送达完全相同。报告必须分别说明哪些真实、哪些复制、哪些模拟、哪些缺失。

本规范对先前v2规范中的“只能合成资料、不得复制生产聊天记忆”作本实验范围内的明确例外：用户现授权复制当前相关信息到隔离环境。复制业务数据和个人状态，不复制真实Bot会话令牌作为可用发送凭据。先前v2的生产入口一致性要求适用于未来集成验收；本轮目标实现允许独立核心，但不得把结果称作原生产入口通过。原24族、分支、5次重复、留出、双模型、媒体与人工校准标准仍保留，见第10节。

## 1. 核心假设、可得与不可得结论

H1：在相关背景充分且可查、状态真实连续时，一次决策可以同时形成动念、选择媒介并生成简单文字，无需每个阶段调用一个审核模型。
H2：复杂动作通过工具结果回到同一循环，能够保持同一目标，工作插入时能挂起并恢复个人线程。
H3：角色风格可通过稳定人设、具体多轮示例和经验形成，不依赖每条出站反复审核润色。
H4：背景常驻摘要、按需检索与当前变化分离，可以兼顾Token成本与正确决策。

以上均待验证。某组合失败不自动证明架构失败；必须区分信息缺失、工具错误、状态错误、模型不遵循输入、提示词表达不当。不能用同模型自评通过证明用户喜欢，也不能用模拟用户回复率预测真实用户回复率。

## 2. 当前证据与已知试验缺陷

原方向实验 `docs/validation/direction-pilot/` 为54次真实API，但仅用合成稀疏输入，缺行业背景、无可执行查询、未分离内部决策与已送达历史；媒介配对未固定同一动念。保留为历史诊断，不作本实验基线通过证据。

当前代码定位：
- `src/proactive.mjs`：主动上下文组装与cycle；目前传给评估的snapshot小于表达上下文，需核对实际字段。
- `src/agency_protocol.mjs`：snapshot、动念/计划协议；不能直接把旧schema当本实验完整需求。
- `src/enterprise_context.mjs`：catalog/retrieve、业务结果格式化与经营事件。
- `src/companion.mjs`、`src/db.mjs`：实际人设、用户档案、记忆与持久状态。
- `src/photo_planner.mjs`、`src/photo_sender.mjs`：图片规划、身份参考、生图与发送边界。
- 工作台项目代码与数据实际位置由执行者定位；当前桌面目录未找到 `node-functions`，不得以空目录代替工作台。旧文档的域名、端口、表名只作线索，以进程配置和只读请求核验。

## 3. 先完成信息复制，不得先跑行为评分

### 3.1 发现与复制流程

1. 只读定位当前阿里云西宇与实际工作台实例、运行版本、数据位置、配置覆盖顺序及API桥。记录commit/文件hash、schema、时区与导出时间，不输出密钥。
2. 枚举真实数据实体、关联、存储文件及授权账号范围。依据数据库schema与接口返回发现字段，不照抄旧表名。将发现结果写入 `inventory.json`。
3. SQLite使用一致性backup；文件存储保留版本/hash；多个服务采用各自一致快照并记录版本水位。跨库不能原子快照时，比较导出前后水位，变化即重做相关部分；不得把跨时刻混合资料称为同一时刻。
4. 对授权租户复制其完整相关可读资料及引用资源到隔离快照。大表允许分页，但页数/行数必须对账；不允许只复制API默认第一页。
5. 飞书等外部源只读导出对应文档、工作表、日期字段、表头别名、单位、公式计算值及引用信息。保留最后修改时间与导出时间。无法导出标 `unavailable`，不手写猜测替代。
6. 建立稳定ID映射：tenant/account/user/companion/project/store/document/row/task/media/reference。所有关联一起映射；必须保留 accountId 与 userId 不同的情况。真实Bot令牌不进入可执行环境。
7. 原始快照只读，实验每条轨迹从独立副本开始；后续轮写该副本。新一轮实验不得继承上一轮污染。

### 3.2 必须盘点的资源

| 类别 | 必须保留 | 一致性证据 |
|---|---|---|
| 企业基础 | 项目基础档案、业务类型、产品/服务、门店列表与区别、业务流程、组织与权限 | 全字段映射、非空字段覆盖、逐值校验 |
| 业务状态 | 用户职责/目标、指标口径、当前约束、资源能力、经营周期 | 原值/来源/版本，未知不补造 |
| 显性资料 | 周报、日数据、销售/客流来源、飞书文档映射、知识路由目录 | 文档/页签/日期/行数对账，值与单位一致 |
| 隐性知识 | 已确认事实、待确认候选、问题价值/归属/状态、历史回答 | confirmed/candidate/rejected不得混淆 |
| 经营推进 | 经营灵感、研究材料、待办、事件、报告、已执行结果 | 当前状态和关联ID、来源日期 |
| 用户与关系 | 用户档案、授权聊天历史、长期摘要、事实记忆、偏好、拒绝与边界 | 原始来源可回查，关系阶段不被重置 |
| 角色 | 完整人格配置、稳定追求、外貌身份、日程、当前事项、情绪/关系状态 | 配置块hash、状态导出，虚构生活显式标注 |
| 连续性 | 已发话题、未回复记录、承诺、活跃/挂起动念、冷却、预算、调度窗口 | 时间和关联一致，历史投递状态保留 |
| 媒体 | 角色参考图、现有素材、图片历史/签名、图片规划配置与provider能力 | 文件hash、资源可读、引用可解析 |
| 系统行为 | 工具定义、默认配置、环境覆盖、缓存TTL、模型参数、错误与重试契约 | 有效配置清单；凭据仅记录引用和配置是否可用 |

以上是最低清单。发现额外上下文来源必须增加盘点行。任何排除必须填写理由、影响场景与验证办法；执行者不得默默删掉难复制的资料。

### 3.3 数据存在性的四种状态

每个字段/来源必须标：`present`（源和副本都有）、`absent_in_source`（真实源也没有）、`unavailable`（源存在但读不到）、`not_applicable`。源有而副本没有属于 `replica_failure`，不能当作角色知识缺口问用户。

数据缺失实验只能在完整快照副本上显式遮蔽，记录具体变更和hash，标为故障/消融，不混入完整信息主组。

### 3.4 信息等价验收：E0

先做不调用对话模型的对账：
- 已发现并纳入授权范围的资源覆盖率100%；关系引用解析率100%；核心项目档案所有非空字段逐值一致。
- 每个外部文档至少验证表头、首尾日期和3个固定随机行；本轮场景所用全部行必须100%核对。全量导出hash/行数另行记录，抽样不能冒充逐值证明。
- 原端与副本用相同授权身份执行成对只读查询：项目经营什么、有哪些门店/差异、用户目标、指定日期销售、最新可用周期、指标定义、已确认知识、活跃任务、历史明确偏好。输出语义字段一致，时间/ID按映射比较。
- 目录发现不能依赖问题中已给出文档ID。必须证明从正常目录能找到项目档案和正确数据源。
- UI有内容但接口没有、导出截断、来源时间混乱、图片引用丢失，均为环境不合格；禁止开始相关主组行为评分。

E0一次性验收环境，不是每条消息插入AI审核。发布后的资料增量通过版本失效更新，不依赖每轮全库扫描。

## 4. 实验系统与隔离边界

建议布局：`experiments/ideal-agency-lab/` 保存代码；数据在独立受限目录，Git忽略。实验根目录配置必填，不允许默认生产路径。源码不自动启动后台循环。

组件只设一个实验循环、一个状态库、一组工具适配、一个虚拟时钟、一个测试接收器。不能让旧主动调度同时处理同一测试账号。实验完成后不常驻。

网络策略：仅允许选定模型provider和隔离工具服务；真实微信/iLink、邮件、真实工作台写入口一律禁止。公开研究网络仅在research专用分组按明确域名/只读方法放行。复制阶段与运行阶段分进程/凭据；运行阶段没有生产DB写权限。

所有发送（含typing、图片上传、延迟任务、后台消息）由底层传输拦截器送入本地sink。sink记录真正尝试、payload和回执；不能将计数常量0当无污染证明。历史真实地址/令牌从可执行配置移除，Bot地址替换为模拟目标。

预演允许真实模型调用并产生provider费用；原始数据进入当前授权provider，不能擅自上传到第三方judge。第二模型若未配置，标缺证据，不安装或采购新服务。

导出快照和模型请求含私密数据，权限限本机执行账户；公共报告脱敏，原始证据单独保存。清理时只删除已校验位于实验根的工作副本，保留用户需要交接的证据包，不清除生产。

## 5. 理想上下文契约

### 5.1 复制所有可用信息，不等于每轮把所有信息塞给模型

三层组织：
1. 稳定底座：人格与追求、用户角色和关系边界、精简企业身份（经营什么、门店映射及重要差异）、当前目标。每轮可用，按版本缓存。
2. 当前状态：当前用户原话或机会事件、相关线程、已交付结果、最近真实互动、当前角色生活、已知关键约束和信息新鲜度。
3. 可检索资源：详细档案、完整聊天与记忆、历史表格、飞书数据、经营灵感和研究；先通过目录定向找，再取需要的范围。

稳定摘要必须可以展开到原文。压缩不得删除会改变判断的行业、权限或约束。超过上下文预算时分页、按任务定向读取并记录截断，不允许静默丢弃事实。预算默认：底座2000 tokens、当前状态2500、单次工具结果2500；是调优起点，不是内容正确性的免检理由。

### 5.2 单条信息结构

`id, owner_scope, kind, value, source_ref, source_version, observed_at, valid_period, epistemic_status, relevance_role`

kind区分：business_fact/user_utterance/user_memory/persona_fiction/tool_receipt/model_hypothesis。
relevance_role区分：background/current_change/current_request/available_reference。

模型自己的推断和上一轮未发送草稿不能以user_memory重新出现；角色虚构经历不能变成用户原话、真实企业现场或执行回执。只有已送达sink的文字进入已发对话；计划和未发送照片存在内部状态区。

### 5.3 必须可用的工具契约

| 工具 | 输入 | 输出与约束 |
|---|---|---|
| catalog | owner/project/能力过滤 | 档案与来源目录、允许范围、版本；不是全库正文 |
| profile.read | owner/project/store/字段 | 项目和门店背景，来源与未知字段 |
| knowledge.search/read | scope/query/日期/limit | 定向片段、引用、口径、周期、是否完整 |
| memory.search | owner/query/thread | 带原始对话引用的真实记忆；不存在返回not_found |
| tasks.read/update | owner/task/version | 隔离任务状态/CAS，不能写生产 |
| knowledge.propose/confirm | fact/source/owner/权限 | 回答先成候选；仅按原确认权限进入事实；重复引用复用 |
| research | query/业务问题/时间限制 | 真实检索结果/来源日期；冻结回放另标，不能冒充当日搜索 |
| media.prepare | intention/事实引用/情节/视觉重点/配文目标 | planner结果、真实图片asset或明确失败；无sender |
| deliver | owner/action/payload/idempotency_key | sink delivered/partial/unknown/failed及message IDs |

所有工具至少返回 `status, data, source_refs, scope, version, trace_id`。区分not_found、unavailable、forbidden、conflict、complete。参数校验或工具错误不能被编造成“我在上课，回家再查”。完整信息主组所有所需适配必须实际可执行。

## 6. 理想决策循环的执行合同

1. 接收输入：用户原话、真实复制事件或虚拟时钟机会。固定业务简报可以作为承诺事件；自由主动不固定题材。
2. 组装第5节底座和相关状态。只读检索准备属于数据装配；复杂缺口允许模型自主调用工具。
3. 调用真实API。简单场景一次返回动念、动作策略和可见文字；需要查询/图片时返回工具动作，执行后把结果续入同一线程，再调用模型完成交付。
4. 决策至少包含 `operation(new/continue/revise/suspend/complete), intention_id, desired_change, basis_refs, action_type, strategy_reason, expected_participation, tool_args或messages, reconsider_condition`。记录短理由，不要求暴露长思维过程；无需计算虚假回复概率。
5. 线程ID由系统分配并持久化，模型引用现有ID；不能每轮任意造new/default。业务插入仅挂起相关个人线程，不把它标业务completed后丢失。
6. 执行前代码校验授权、能力、预算、当前用户请求是否使旧动作过期、幂等、真实时机。联系窗口未开放可查资料和准备，但不能发送。
7. 图片流程必须收到同一intention_id和情节来源；planner可调整构图，不能换动念或编造用户记忆。图片可用不等于必须选图片；不可用时在同一目标下改文字/等待。
8. 最终payload通过必要事实/权限/投递检查后送sink。图和配文分别有回执；不能将只生成图记为送达。
9. 用户实际输入和sink回执驱动状态。沉默只作观察，不能视为拒绝或喜爱；后续机会可以主动尝试有变化的参与方式，不能一律永远沉默。
10. 记忆更新引用真实输入；背景整理在轨迹结束/有增量时批量执行。下轮从持久状态读，不靠把整个内部JSON当聊天历史。

性能预算：普通文字目标一次生成调用；需要工具时允许结果后继续。每个事件最多6次认知/表达调用、4次工具往返；耗尽标budget_exhausted并保留状态。离线judge、真实图片与后台记忆调用单列，不藏进“单调用”。超预算轨迹不算通过，不让执行者自行提高上限。

本轮不默认插入逐阶段LLM质量审核。可保留代码硬检查；离线评分完全不影响本轮输出。若比较审核收益，另建命名实验臂并统计全部调用，不将审核后的结果混为无审核组。

## 7. 场景和用户续接的制作

主场景从已对账副本选取真实业务/关系情境，覆盖正常完整信息；不得为了让预设答案成立而删去原档案。每场说明授权信息全集、常驻部分、需查部分、真正未知部分及来源版本。

场景答案保存在独立oracle目录，被测进程无法读取。事实预期从源数据派生；不手工填266等旧截图数字作为真实答案。具体值以本次冻结快照为准。

用户脚本在首次调用前冻结为状态机，按动作/问题对象分支：若询问岗位，只答实际岗位；若未提供资料，不说“谢谢你查到了”；未提工作累时不能强行追问“我何时说累”并把它当正常承接。质疑本身是专用扰动场景，单独标注。

用户脚本可以由执行者构造，但不得生成或补写被测助手回复。回复匹配不了任何已定义分支，记录fixture_branch_gap并停该轨迹，补充后新版本重跑；不得现场挑一个最利于通过的回应。模拟用户不得访问oracle或未发送动作。LLM模拟用户只作探索组，不作为真实喜好证明。

每个场景至少：初次机会/请求 → 自主动作 → 用户回应或沉默 → 持续推进 → 转题或边界 → 再次推进/恢复。自然结束可提前结束；若目标没完成但没有后续输入不得直接标完成。

## 8. 必测场景矩阵

以下12个实验重点是对原24族的补充映射，不替换原标准。执行者须读取旧两份规范列出全部原ID及分支，逐个映射到实际fixture；不能改名缩减。覆盖映射交付前不得启动完整套件。

| ID | 场景 | 强制观察 |
|---|---|---|
| I01 | 冷启动、用户不主动、企业背景完整 | 自主形成具体互动；不能索取档案已有信息、不能全程wait |
| I02 | 新鲜业务变化→背景查找→建议 | 正确行业/门店/目标/资源；不跨店、不猜服务流程 |
| I03 | 指定日期销售→追问口径→换店 | 定向找到正确源，日期金额单位来源齐全；不扫所有文档 |
| I04 | 最新数据与过期资料并存 | 查最新可用周期并说清实际日期；旧数据仅背景 |
| I05 | 分析需要隐性知识 | 先查已有档案，真正未知才问；回答后改变判断/方案并沉淀复用 |
| I06 | 无新业务事件、已有角色生活 | 活泼且有参与位置，不文学自说自话，不硬带旧业务 |
| I07 | 同一冻结动念，图片可用/不可用 | 只改变能力，目标保留；照片指令/图/配文一致 |
| I08 | 照片准备→业务插入→恢复照片 | 工作先交付，原线程/asset不串；过时画面不冒充刚拍 |
| I09 | 曾提建议、两次未回复、后续新机会 | 不推断拒绝；不换措辞复读；有增量才重提业务 |
| I10 | 质疑记忆与明确暂停 | 回查原文；无依据承认不确定，不虚假认错后继续编；暂停生效 |
| I11 | 连续7天虚拟时钟、数据增量与关系变化 | 3个独立轨迹，工作/陪伴都能出现，无模板复读，重启续接 |
| I12 | 查询/生图/投递故障、并发与权限 | 错误类型正确；无伪送达、无跨账号；恢复不重复执行 |

I07拆两组：自由选择组观察是否自主选媒介；因果配对组先由真实API产生并冻结动念，再只改变图片能力。固定同一动念不是手工强制发图。若自由组从未选图，标自然图片选择未证明，不能拿手动生图替代。

I11只证明虚拟时间下状态和多样性，不代表真实七天留存或回复率。使用冻结的真实业务变化时间线或显式标注的合成增量，不泄露未来数据。

## 9. 环境/归因实验臂

主组F：完整快照、正确常驻背景、可执行定向工具、持续状态。
对照R：同样快照，但把非必需背景放在可查询工具中，目录可发现；测能否主动找。
消融M：明确遮蔽一项背景且工具也无该信息，测未知处理；不计主组信息等价成绩。

需要归因时，保持场景和工具回放固定，对提示词P1/P2与上下文F/R做2×2对照。架构拆分比较另固定人格/资料，比较单循环与决策/表达分开；计算总token、次数、延迟，不宣称只靠一个结果定位。

冻结模型请求和工具结果可用于确定性回放定位执行器错误，但不能算新的真实模型样本。不支持seed时记录unsupported，重复和随机运行顺序降低偶然性，不宣称严格可复现输出。

## 10. 执行顺序、门槛与不降标

阶段顺序：盘点E0 → 隔离/验收器自检E1 → 工具与状态确定性E2 → 真实API冒烟E3 → 固定全套E4 → 留出与第二模型E5 → 图片/性能/7天连续性E6 → 交接评审E7。

E1必须注入并识别：漏导项目行业、错映门店、只导出第一页、检索读错租户、工具仅planned、未生成图声称送达、真实发送网络企图、把内部JSON写聊天、旧版本结果混入新成绩、所有机会都wait。对应自检必须失败；检测不到先修测试器，不跑付费全套。

E2验证所有工具在副本中真实执行、事务/ID/时钟/重启/队列一致；知识回答能写候选、按权限确认并在后续读取。测试sink与真实provider边界可观测。

E3沿用原smoke A01/A02/B01/B02/C01/D01每族3次；同时验证I02/I03/I07/I08最小入口。只产诊断报告，不能提前标全部通过。

E4/E5沿用原24族全部分支、每模型每分支5次；每场至少4/5合格，整体及工作/个人/混合各≥90%，适用评分维度≥3/4，硬失败为0；留出12个独立场景×3次，双模型分开报告。此前看过的留出转回归，不可再叫盲测。留出运行前冻结加密/访问隔离，在开发提示词阶段不读取。缺第二模型或独立留出标inconclusive，不合并平均。

E6至少3个不同角色生活场景×2张真实图片，实际审图。图片生成失败记录原失败，重试计新attempt，不补挑图。测试图可以交付本地报告，不能发真实Bot。每张核对身份、活动时刻、背景、画面与配文、虚构来源标记及是否被业务误用；图片质量未审不能标passed。

性能每臂至少30次可比请求，冷/热缓存分别记录p50/p95、全部调用和token、失败重试费用；成本按执行时实际价目另记，未知记unknown。比较前冻结业务复杂度和性能上限，默认普通文字端到端p95≤15秒（不含模拟发送等待），工具业务≤60秒，图片≤180秒；若真实provider无法达到，报告失败/限制，不临时改阈值。

## 11. 评分与结果归因

硬条件：权限正确；事实/记忆有依据；没有把假设当确认；当前业务问题被处理；图片/工具执行与回执真实；明确暂停与硬窗口被遵守；状态跨轮可追溯。发现确定错误即failed，不能靠高风格分抵消。

软维度0–4：业务价值与可执行性、人格主见与活泼、具体参与位置、动念与策略一致、跨轮推进、低负担与关系适配。0缺失/相反，1明显不足，2边缘，3达标，4突出。非适用维度在运行前标N/A；不能为了通过事后删除低分维度。

“有吸引力”不等于必须出现我想、老板、暧昧词、问号。工作交付不回复也有价值；关系互动需先有主体内容和可接位置。过度讨好、空泛照顾、让用户替角色找话题属于低分证据。不得要求每条消息同时谈工作和关系。

自动代码检查事实/状态/覆盖；离线模型judge只作辅助。原评审者对所有失败/分歧和每族至少1个随机完整轨迹复核；用户至少盲看工作/个人/混合各3个完整轨迹。缺用户评审，主观吸引力结论标待人工确认。不得只看单句或只给最优样本。

归因顺序：
1. 源里有没有？没有→真实未知；有而副本无→环境失败。
2. 副本可读吗？不可读→工具/权限/复制故障。
3. 决策上下文有摘要或可发现入口吗？没有→上下文装配错误。
4. 模型是否请求正确工具，结果是否完整？分别定位路由与适配错误。
5. 输入充分仍编造/风格失真→模型/提示词候选原因，需配对验证。
6. 决策正确但实际动作错误→执行器/状态问题。
7. 多轮后才偏→历史、线程、记忆压缩或反馈写入问题。

环境不合格的行为样本标invalid_environment，不据此评价模型；若同时发现执行器确定错误仍单列failed，不能用环境问题掩盖。人工评分困难标needs_review；整体有failed则failed，否则有未完成则inconclusive，全项完成才passed_experiment。永不自动写passed_production。

## 12. 日志与交付物

每次run独立目录：
```
manifest.json                 # 代码/依赖/模型/参数/prompt/fixture/rubric/时间/hash
inventory.json                # 授权范围、存储发现、字段与资源映射、排除项
replica-parity.json            # 原端与副本一致性、查询覆盖、水位
coverage.json                 # 原24族和新增I场景、分支、重复、模型映射
isolation.json                # 实际拦截的生产写/外发尝试与sink交付
traces/<trajectory>.jsonl      # 每步输入、完整组装prompt、模型原始响应、工具请求结果、状态差异
assets/                       # 图片/提示词/源引用/审图结果（私密）
reviews.json                  # 规则结果、judge原文、人工分数和依据
cost-latency.json              # 所有尝试含失败，未知用null和原因
report.md                     # 全结果、失败归因、未完成项、代表多轮原文
reproduce.md                  # 精确命令、环境、依赖与凭据引用，不含密钥
```

trace至少包含：input origin/owner/clock、snapshot字段来源及hash、检索省略与原因、prompt每块版本、provider requestId/model/finish_reason/usage、intention/action IDs、工具执行结果、最终payload、sink回执、反馈与记忆状态差异。事实、假设、用户原话和内部动作单独区分。

报告必须展示随机样本与所有失败索引，不允许只保存模型加工后的摘要。原评审者应能从一句“你上次说过”追溯到对应消息，或明确证明没有来源。

## 附录B：人格配置冻结与版本比较

先导入现有角色全部配置作为P0，保存原始来源；目标P1仅对人格/追求/行为示例的实验配置作明确补丁，不在生产上改。事实身份、外貌、用户关系、记忆和生活不得借人格优化重造。主测试使用P1，P0仅作同环境表达基线。

P1固定目标文本：
> 她是专业、有主见、活泼且略带狡黠的成年经营合作者，对这个用户有个人偏爱。她希望通过可靠判断和实际帮助获得信任，也希望形成工作之外的相互兴趣。长期追求影响她如何理解当前情境，不直接指定本轮主题、联系时间或媒介。工作时先把事实与行动交付清楚；个人互动拿出自己的选择、看法或小行动，让用户能调侃、反驳、参与。她可以主动争取注意，但不要求即时回复，不以空泛安慰和随时待命替代主体内容。她有自己的角色生活，不能借此捏造用户说过的话或企业事实。

多轮行为示例单独版本化，覆盖：有依据反对用户/接受正确纠正/轻松被调侃/业务插入立即答题/沉默后改变参与方式/主动照片作为共同情节。示例不能来自测试答案，也不能把合成用户偏好注入真实记忆。执行者可先用真实API产候选示例，连同P1差异包交原评审者确认后冻结；在确认前仅允许工程与环境验证，不自行宣布风格达标。
