## 4. 将最小连通性探针与完整实验分开

先在可信gateway发一个不含企业/用户资料的最小请求，验证实际渠道确实可调用。该探针不运行worker、不读取oracle、不发送Bot、不改任何生产状态，因此不依赖企业快照身份和完整worker隔离，也不依赖第二模型、图像、人审或数值预算证明。

新增或复用唯一CLI子命令provider-probe，使用第3节自动解析的binding。请求为简短固定技术文本，限制输出token；不把它计为角色样本。记录实际模型标识、HTTP状态、非敏感响应文本、finish_reason、usage及延迟。不能把HTTP200或公开health等同模型回答成功。

只允许沿原规范最多2次瞬时基础设施重试；认证错误不反复重试，不切换陌生渠道。失败分类network/auth/quota/protocol/provider_error，保留脱敏错误。出现真实错误才说服务不可用或凭据失效。

此步骤成功后应立即给用户一条简短进度：“已通过项目现有渠道收到真实模型回复，尚未做角色效果验收。”不要等再做数轮fake测试才报告。

## 8. 真实调用顺序及门禁范围

| 阶段 | 依赖 | 产出 |
|---|---|---|
| P0最小provider探针 | 自动读取当前binding；有限调用 | 一条实际模型响应，不含企业资料 |
| P1主模型smoke | 源/隔离合格、主模型已通、测试版本绑定 | 真实上下文→工具→答复与费用记录 |
| P2三臂108条 | P1基本执行正常、K场景合同合格 | 每臂每场3次；真实对话和配对结果 |
| P3原完整套件 | 候选修复及冻结 | 原次数、R/I、第二模型、留出、图片、7日、性能 |
| P4复核交付 | 自动结果齐全 | 最差样本、匿名盲评包、最终结论 |

P1显式指定当前主模型，走sample_generation；第二模型不能挡P0/P1/P2。当前没有第二模型时先完成主模型阶段；到P3从已有授权配置查找，确无可用第二模型再单列迁移性未验证，不能杜撰第二模型。

图片沿既有图片渠道，由同一动念选择；无可用图片配置只阻塞对应图片分支，不阻塞纯文字。FROZEN研究使用已冻结真实来源，LIVE研究另列，不要求所有FROZEN调用具备实时搜索provider。

费用状态写user_authorized_existing_provider_testing，无数值上限字段可为null，禁止用null假装无限预算或用0冒充免费。仍按规定有限轨迹、有限重试、事件调用上限执行；持续记usage和费用，价格未知标unknown，不阻塞已授权调用。不得循环刷样本直到好看。

真人盲评只阻塞最终主观结论。评审材料由执行者从全部真实轨迹生成，用户不负责提供review materials。

## 9. 修复迭代和结束标准

P0失败先修配置/协议，不做角色prompt修补。P1失败按来源→上下文→模型动作→工具→状态→投递定位。工程缺陷用确定性反例，选择/表达缺陷用固定条件prompt对照。A/B/C不得混入不同数据或不同模型参数。

每次修复保留前次原响应、版本、归因和回归记录。执行原定失败场景及相邻场景复测，再完整验收；不删失败、不降低门槛。测试完成但质量不够可以如实failed，不能保证一定通过；任务尚有可完成工作不以“调用前被门禁拦住”结案。

不新增在线逐层LLM审核、不重造runner、不启动真实Bot、不自动集成生产。最终附生产接入差异清单：哪些实验模块需接回原生产责任模块、哪些迁移/回归尚未执行。
