# 溪语与经营知识融合：本轮实施及验收

后续记录：[2026-09-06 关键知识真实模型闭环、修复及验收边界](enterprise-continuity-2026-09-06.md)。本文保留 9 月 5 日当时状态。

日期：2026-09-05。本地运行，未部署。

## 本轮边界

沿用语境路由、知识桥、候选审核、原有人格生成、内心独白和主动调度；不新建第二套聊天、记忆库或 Agent 执行平台。

## 已修改

1. 工作路由在原模型请求中增加 support / lookup / explore / delegate 意图和 replyToActiveTask。短回复不再直接强制归入上一次工作任务。纯倾诉不强制检索，工作相关并不自动意味着需要写库。
2. 查数缺记录不再直接发送固定系统句。微信与网页均复用人格生成；共享事实校验保留数值；null 不再当零，昨天/今天不能用整周汇总替代。
3. 工作表达规则集中到 config/prompts/work-response-v1.json，独白与最终答复消费同一模块的不同职责提示。没有新增模型调用阶段。独白得到交流意图，不再把正常查数无依据解读成关系挑衅。
4. 现有提炼模型获知活动任务。只有直接回答任务的候选才关联任务，充分回答才关联知识缺口。无关新信息不自动关闭原追问。所有新知仍先待人工确认。
5. 经营事件成为原 normal 主动消息机会中的素材，沿用原调度拒发、配额和安全门；不覆盖早晚安、提醒、关系修复。修正 knowledge_gap_followup 与 knowledge_acquisition 类型映射；发送早退不再登记成功。
6. 工作台修正知识缺口模型返回值层级和 token 参数。已确认隐性知识按门店进入经营灵感/每日分析上下文和经营地图节点分析；知识修订参与每日上下文指纹。规范新候选门店 ID 到门店名的映射。
7. 修复待确认信息页 MutationObserver 重复改写自身而造成持续刷新的问题。

## 验收标准与结果

| 标准 | 本次结果 |
| --- | --- |
| 日查询不能报周汇总，缺失不报零 | 确定性测试通过 |
| 工作查数最终有回复，不只说去查 | 网页真实 API 测试有最终缺数答复 |
| 倾诉不被工作任务强行接管 | 网页从查数转“先别分析，哄哄我”，显示生活对话，经营资料 0 条 |
| 工作新知仍先待确认 | 原知识桥测试通过，未应用真实候选 |
| 无关新知不关闭追问 | 新增隔离测试通过 |
| 主动知识类型正确拉取，生活短句不被回绑 | 主动知识 smoke 通过 |
| 原异步任务不回退 | check_deferred_work_task 通过 |
| 待确认页面可打开且响应操作 | 浏览器实测通过 |
| 语法/静态检查 | 修改的溪语模块 ESLint 与工作台后端 node --check 通过 |

真实外部模型探针复用现有 companion 和 API，读取真实资料，不将探针对话或模拟候选写入企业库。浏览器另发送了两条实际回归消息，保留在聊天记录中；没有改写飞书表格。启动 DB 时原有初始化逻辑仍可能补齐偏好记录，探针不等于数据库字节级零变化。

## 尚未完成或不能宣称通过

- 人格自然度仍有波动。网页缺数回复出现过“要不要明天我核对下工作台再告诉你”这一不必要提议；并没有由此创建明天任务。不能把这一版宣称为语气一致性全面通过。
- 主动消息本次验证了调度接入、过滤和任务回绑，但没有进行连续多日真实微信投递验收。原经营主动开关/用户策略未为测试强制开启；设定汇报时间现为可参与主动机会的起始时间，不保证到点必发。
- 自动控制 WorkBuddy、外部执行后的任务回执、完整多轮方案版本跟踪没有在本轮新增或宣称已完成。讨论产出仍在对话中，明确提炼的打法候选仍走原工作台人工确认到打法草稿流程。
- 日数据只在可安全匹配时使用；本轮没有新做从来源表自动获取昨天日报的独立管线。
- 缺口模型解析已修正，但尚未用真实企业数据完整验收“生成新缺口→主动发出→回答→审核→下一轮机会改进”全周期。
