# 溪语关键知识闭环：实测、修复与当前边界

日期：2026-09-06（北京时间）。本地完成，未部署。

## 本轮结论

“生成关键知识缺口 → 原人格主动发问 → 工作回答提炼 → 候选审核 → 入库 → 后续检索与经营分析复用 → 下一项问题”已在隔离数据副本中使用真实配置模型跑通。原有确定性回归及新增状态回归通过。

这里的“真实模型”不等于真实员工的长期经营验收：企业背景和记录来自现有本地资料；运营者回答由测试夹具模拟，人工确认动作由测试脚本在副本中执行。未将模拟回答应用到真实候选箱或正式企业资产，未向微信发送测试消息，未写飞书。

本地正式环境另生成了 4 条待补充知识缺口，未自动确认任何候选。入口：工作台 → 待确认信息 → **关键知识 · 优先补什么**。可查看为什么值得补、应向人询问还是查数据/外部来源，并复制带目标、来源、交付物、验收和权限边界的任务说明。

## 对三项目标的实际改善

| 目标 | 本轮实现与证据 | 尚不能宣称 |
| --- | --- | --- |
| 有情绪价值，愿意陪人开始工作 | 主动问题带决策理由和最小回答要求；原人格表达；疲惫/不聊工作回到陪伴，不关闭未答任务，不以亲密作为工作交换条件 | 真人感、主动情绪与“哄人上班”尚无多日用户体验验收；样本中仍有重复“念书/躺会儿”等套话及未兑现的小提议 |
| 补最关键知识并沉淀复用 | 价值排序、获取路由、待审核停问、拒绝后重开、所有适合的确认资产统一结题、按门店隔离、已答问题去重、知识变更使下一轮分析失效重算 | 排序是模型估计，尚无实际收入改善数据；语义去重仍是轻量相似度，不保证所有同义表达都识别 |
| 懂业务并交付执行方案 | 新知识进入溪语、日常灵感和经营地图；回复约束要求任务输入/步骤/交付/验收/停止条件；工作台可复制任务说明给其他 Agent | 没有新增 WorkBuddy 自动控制、跨 Agent 执行回执、连续行业监测或完整方案版本管理；模型建议仍需审阅 |

## 修复记录

1. **供给原来不会自行分析新缺口。** 原主动刷新只消费已有缺口。现在从经营主动机会异步启动缺口分析，按门店缓存；模型分析中不记为一次已完成的知识检查。数据、确认知识或已解决问题变化后可在下一次机会重新分析，保留原频率、睡眠、关系及配额控制。
2. **优先级在事件转换中丢失。** 原事件统一写为 high。现在保留 priority，并按影响、紧迫性、复用价值和回答成本计算辅助分数；source_lookup / internal_analysis / external_research 不占用面向人的主动追问。
3. **缺口需能改变决策。** 增加 decisionImpact、expectedAnswer、assessment、acquisitionRoute、来源引用和历史周期。合法空 gaps 不再被当成失败而自动补一组问题；模型不可用仍有原基础检查降级，不表示关键业务排序通过。
4. **历史数据被叫作本周。** 缺口输入包含日期和自有门店目录；服务端对旧周期使用实际日期，主动表达增加历史周期检查。来源表已有且有效的日快照进入知识检索，不新造独立取数管线。
5. **自有门店被当作竞品，混入另一店信号。** 提示词明确自有门店关系，检索排除只涉及其他门店的信号；原任务范围在提炼时优先，避免模型空 venueNames / venueIds 覆盖东坝范围而成为项目通用事实。
6. **已答问题反复出现。** 不仅按 ID/statement 去重，也比对 question。真实复测发现过“新 ID、同一问题”的假通过，已加强测试与修复。确认资产不只通过搜索分数隐式供给，已有缺口与确认知识也进入发现上下文。
7. **充分回答门槛不断上升。** 仅要求粗略来源时，模型又索要样本量及更细拆分。现在区分本次必须补齐的 missingInformation 与非阻断的 evidenceLimitations；保留“抽样/口头观察”等限定，不升级成因果证明。
8. **审核状态不闭合。** 充分回答保存后 gap 进入 review_pending；未确认内容不可作为事实复用；退回后 open。确认适合资产后 gap 进入 confirmed，事件 acknowledged。曾仅隐性知识路径结题的问题已修复；冲突需明确人工确认后应用，经验草稿不作为正式经验检索。
9. **主动生成自己猜答案。** 真实样本把回答示例“一半”当猜测。去除验收要求中的虚构示例，强调仅提问，增加历史时间与无依据比例检查；失败复述一次仍不合格则不发。去重重生也必须保留原业务问题，不能换成生活话题后仍绑定原任务。
10. **复用不完整。** 现场事实等确认资产进入每日经营及经营地图上下文；隐性知识继续按门店进入分析；目标、决策和约束进入溪语工作上下文。补充票数、接待人次、场域客流的口径约束，禁止直接相除当独立成交率；“未观察到异常”不能等于排除所有外部影响。
11. **浏览器打开页面会回写旧数据（本次实际触发，已恢复）。** 旧页面把所有 localhost 的运行数据/候选/飞书同步接口写死为 4174，导致 4175 隔离页面也访问主服务；初始化又把旧缓存与服务器数据合并并自动 PUT。在页面验证后发现 records 等内容被旧缓存覆盖。已保存事故状态备份，并恢复验证前 records、reports、workbench、experiences 的完整业务 data，提升 revision 防止旧页面继续覆盖；intelligence 始终未变。HTTP 页面现使用同源接口，成功读取服务端后以服务端为准，旧浏览器内容只留本地恢复备份，初始化不再写回，读取失败不开放写入。修复后再次打开页面并比对，五类业务 data 全部与验证前一致，见 source-state-restored.json。

## 2026-09-06 后续架构调整

今早真实主动触达暴露出业务策略仍关闭、普通动力判断未向生成器传递意图、表情素材不可用等问题。已完成诊断、社区选型和第一层主动意图接线，见 [持续欲求与主动意图研究](proactive-desire-research-2026-09-06.md) 与 [冷启动主动联系验证记录](validation/2026-09-06/initiative-cold-start-validation.md)。跨重启持续意图、后台业务监控和行动规划仍是待实施能力。

以后调整这些逻辑先看 [溪语逻辑原点与维护地图](xiyu-architecture-maintenance-map.md)。仓库根目录 `AGENTS.md` 已要求后续 Codex 沿唯一原链路修改，禁止另建第二套调度、意图、记忆、业务路由或发送系统。

用户指出旧缺口仍是周报异常集合后，新增按来源能力的飞书精确查询，以及自顶向下的企业知识地图。当前入口、调度、实现和限制以 [企业知识路由与认知地图](enterprise-knowledge-routing-2026-09-06.md) 为准；本文件上面的四条历史缺口不再代表企业知识建设主线。

## 后续验收边界

最优先的是让真实运营者回答队列里一条有价值的问题，人工审核后看下一轮问题和方案是否因此变准。当前没有对外代发测试消息，也没有实际业务增益结果。

行业新消息目前仍依赖原有外部检索能力；本轮增强了获取路由和带链接/日期的证据要求，以及可复制的检索任务，并未新增每日自动搜索和可信度评审管线。不能声称已经持续掌握行业最新情况。

人格表达和经营建议仍有模型波动：主动开场有时省略问题细节；慰问偶有新的小提议；灵感可能仍需核实设备、人员与许可；长任务说明的格式偶有残留星号。程序状态通过与模型内容完美通过是两回事，不以本轮样本宣称“已完全达到真人业务助理”。

## 2026-09-06 统一主动性与知识深度复核

按用户对“非固定栏目轮播、技术分析所需知识、提高回复欲的沟通策略”的反馈，新增 [统一主动性、企业认知与沟通策略设计](unified-agency-and-engagement-design-2026-09-06.md) 和隔离实测 `validation/2026-09-06/agency-knowledge-probe.json`。

复核结论是：12 维适合作为目录，但当前一条回答即将整维标为 `documented`，不足以支撑具体技术分析；现有关系动念拥有真实性和不催回复的守卫，却没有给普通主动联系提供足够的内容钩子，也没有统一选择文字、经营交付、提问、照片或先静默工作的策略。本文档明确记录该边界；本轮没有让尚未验证的新选择器接管生产发送。

## 2026-09-06 实际改造结果

上述设计随后已接入本地生产代码：`initiative.mjs` 改为统一根本欲求和候选动念选择；普通照片不再预占固定日程，只在真实生活事实或已核验手头事项形成情节时参与竞争；普通关系开场增加“具体钩子、主体内容、容易接住的落点”，无事实时禁止制造路过、朋友圈、同事和共同记忆作为由头。

工作台知识地图升级为 v2：12 维下拆分分析切面，一条回答只产生 `partial`，依赖在部分掌握后可继续推进；问题生成带 `facetId` 和答案摆动测试。实测还发现主动问题的明确回答可能被路由模型标成 lookup、导致不进入审核，已改为只要可靠回绑到有效经营任务就强制进入提炼与人工确认。

经营灵感新增语义身份字段：问题范围、原因假设、解决机制、作用对象、实质新增和 semanticKey。生成时读取历史灵感；问题、原因、机制和对象相同的内容不能靠换标题再次出现，只有新证据、新机制或新执行步骤才允许重提。用户未回复仍保留为开放状态，不当作拒绝。
