# 来源表批量取数

## 来源

运营填数台通过后端 `POST /api/feishu/source-preview` 读取 `FEISHU_SOURCE_SPREADSHEET_TOKEN`。来源工作簿按门店拆成 5 个渠道页签：大麦、开店宝、抖音、猫眼、小程序。页面只接收预览结果，用户点击“应用所选到当前草稿”后才改变当前周记录。

## 计算规则

- 普通渠道使用每日列：`今日票数`、`今日销售额`、`今日实收额`、`今日核销人数`。
- 小程序额外读取 `今日线下销售数`、`今日线下销售额`、`今日非线下销售数`、`今日非线下销售额`；非线下部分写入“小程序其他”，线下部分写入“线下”。业务中的“分销”通常是这部分线下数据的别称，不再独立累加。
- 来源表“开店宝”在工作台和周报中统一显示为“大众”，但来源追溯仍保留原始名称“开店宝”。
- 日汇总按真实业务日期匹配；周汇总为周期间内每日值之和。
- `总销售票数`、`总销售额`、`总实收额`是累计列，不参与求和。
- 缺失日期不自动当作 0，会在预览中显示缺失。

## 可应用分组

| 分组 | 默认状态 | 目标字段 | 说明 |
| --- | --- | --- | --- |
| 渠道销售额（全部商品） | 默认勾选 | `channel.amount` | 开店宝→大众；小程序非线下→小程序其他；小程序线下→线下 |
| 渠道销售票数（全部商品） | 默认勾选 | `channel.orders`（展示名：销售票数） | 普通渠道取每日“今日票数”；小程序分别取“今日非线下销售数”和“今日线下销售数” |
| 日票房与周票房 | 待确认口径 | `daily.box_office`、`core.box_office_total` | 使用已接入渠道销售额合计，不代表来源表之外渠道 |
| 线上销售额 | 待确认口径 | `core.online_sales_amount` | 普通渠道销售额 + 小程序非线下销售额 |
| 线下销售额 | 默认勾选 | `core.offline_sales_amount` | 小程序“今日线下销售额”；分销同源，不重复相加 |
| 平台实收额 | 待确认口径 | `core.platform_settlement` | 使用实收额合计，需确认与扣佣结算口径一致 |
| 门店销售票数 | 默认勾选 | `core.sales_order_count`（展示名：销售票数） | 汇总各渠道每日票数；内部编码保留 `sales_order_count` 仅为兼容历史记录 |

门店目标、接待客流、场域客流、次卡和播控不由该来源表自动写入。来源表的每日票数字段会同时形成各渠道 `channel.orders` 和门店汇总 `core.sales_order_count`；两者在界面上都显示为“销售票数”，不再称为“订单数”。

## 渠道与次卡的严格边界

- 渠道区统计该渠道售出的**全部商品**，字段只有销售票数和销售额；其中可能包含次卡，也可能包含单次票、套餐等其他商品。
- 次卡区只统计 5 次卡、10 次卡等**次卡商品**，数据必须来自独立 `cards` 字段或明确的次卡来源。
- 不能把渠道销售票数/销售额当作次卡销售，也不能用渠道汇总反推出次卡单数、金额、权益或核销。
- 周报和 AI 分析必须分别读取渠道数据与次卡数据；“渠道变化”与“次卡变化”是两种独立经营信号。

## 统一渠道口径

| 来源表原始字段 | 工作台标准字段 | 线上/线下角色 | 去重规则 |
| --- | --- | --- | --- |
| 普通渠道·今日票数 / 今日销售额 | 同名渠道·销售票数 / 销售额 | 全部商品 | 每日值按真实日期汇总，不使用累计列 |
| 开店宝·今日票数 / 今日销售额 | 大众·销售票数 / 销售额 | 线上 | 不再另建“开店宝”业务渠道 |
| 小程序·今日非线下销售数 / 今日非线下销售额 | 小程序其他·销售票数 / 销售额 | 线上 | 不与线下部分混加 |
| 小程序·今日线下销售数 / 今日线下销售额 | 线下·销售票数 / 销售额 | 线下 | “分销”默认是同源别名，二者只能保留一个 |

工作台预览和录入区会展示包括“线下”在内的渠道拆分，用于完整呈现经营结构；正式飞书 `录入_渠道` 同样写入规范化后的“线下”渠道。若页面使用业务别名“分销”，同步时归一为“线下”，两者不会同时落两行。`录入_周经营.线下销售额` 继续保存门店周汇总；它与渠道明细属于不同粒度，周报不会把两者重复相加。
