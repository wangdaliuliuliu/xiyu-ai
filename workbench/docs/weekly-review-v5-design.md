# 周报复盘结论链路 v5

## 页面顺序

1. 保存结构化周数据与本周经营事实。
2. 点击“识别 / 刷新问题与机会”，生成本周复盘卡片。
3. 因果不清楚时，直接在对应卡片中对话补充事实；历史对话保留，但页面不展示轮次。
4. 点击“生成复盘分析”，模型综合数据、历史趋势、经营事实与卡片问答形成结论。
5. 系统依次生成零到多条经验候选和下一步动作候选；运营可以选择、修改、删除或手动补充。
6. 页面底部出现“生成完整周报”。点击后固定本次选择，输出可复制、可落盘的正式周报。

## 自动化、模型和人的边界

- 程序：数值计算、环比、长期趋势、重要性阈值、来源追溯、流程状态和最终排版。
- 检索层：按门店、指标、时间、渠道或项目检索相关历史结论与已确认经验；命中内容只作为假设参考。
- 大模型：问题生成、回答相关性审校、复盘结论、经验候选、下一步动作候选。
- 运营：提供现场事实和证据，并决定最终保留哪些经验和动作。

模型阶段分别使用 `backend/weekly-review-prompts-v5.json` 中的版本化提示词 ID，并遵守 `backend/report-schema.json`。本地内测模式也走相同的阶段和 JSON 字段，只是由内置提示词模拟器返回结果，不把某一周的答案写死在页面里。

## 落盘边界

卡片问答是形成结论的过程，不进入正式周报。正式留存只包含复盘结论、运营确认的经验和下一步动作；网页本地数据负责草稿防丢，复制出去的完整周报才是正式经营文档。
