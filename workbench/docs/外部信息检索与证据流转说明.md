# 外部信息检索与证据流转说明

## 目标

让公网信息服务于经营判断，但不让搜索结果冒充门店事实或本周因果。所有外部资料先作为候选证据保存，再由运营明确应用。

## 两种资料

| 类型 | 例子 | 默认周期 | 进入位置 |
| --- | --- | --- | --- |
| 一次性/低频背景 | 地址、楼层、场域、自然客流锚点、初始客群 | 首次建立，必要时重新搜索 | 项目档案，按项目/门店隔离 |
| 动态/条件检索 | 当前活动、天气节假日、竞品价格、行业案例、打法证据 | 发现重要信号或生成打法时按需 | 经营地图或打法页的检索任务 |

## 状态机

`候选 → 已应用 → 过期/已拒绝`

重新搜索只能新增候选或新版本，不能直接覆盖已应用资料。AI 只接收“已应用”资料，并在提示词中要求把它当作背景参考、不得用于证明本店因果。

## 数据结构（保存在 workbench 运行状态）

```json
{
  "id": "ev-…",
  "scope": "project | venue:东坝 | venue:中影 | plan:<id>",
  "venue": "东坝",
  "title": "来源标题",
  "url": "https://…",
  "claim": "资料支持的背景判断",
  "sourceType": "web | manual_url | github",
  "status": "candidate | applied | rejected",
  "fetchedAt": "2026-08-31T00:00:00.000Z",
  "appliedAt": "2026-08-31T00:00:00.000Z"
}
```

## 接口

- `POST /api/strategy/external-search`：服务端统一适配搜索、手动来源读取和未来正式供应商。
- 未配置正式供应商时默认使用“手动来源”兜底，避免免费服务器因公共搜索网络波动阻塞页面；生产环境可设置 `EXTERNAL_SEARCH_API_ENDPOINT`、`EXTERNAL_SEARCH_API_KEY`，密钥只在后端。

## 使用顺序

1. 项目档案中建立或更新一次性背景，检查门店范围和来源日期，点击“保存并应用”。
2. 经营地图发现重要且无法解释的信号，或打法需要行业证据时，再创建动态检索任务。
3. 只勾选真正相关的来源，点击“将勾选资料用于本次 AI 分析”，然后重新运行分析。
4. 周报最终只写本店已确认的事实、因果和验证结果；外部资料作为背景出处保留，不替代运营确认。
