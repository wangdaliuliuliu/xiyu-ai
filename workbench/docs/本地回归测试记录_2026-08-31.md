# 周报工作台本地回归测试记录（2026-08-31）

## 测试范围

本次只在 `http://127.0.0.1:4174/` 本地环境执行，未部署线上。测试使用当前服务端已配置的外部模型 API 模式，未切换成本地规则模式。

按真实运营者路径完成：选择周期 → 识别问题与机会 → 补充经营事实 → 多轮因果调查 → 生成复盘分析 → 选择/补充经验与动作 → 生成完整周报 → 复制 → 切换门店复核。

## 已验证结果

- 报表默认周期会优先选择最近一个有数据且不晚于今天的周期，不再默认落到 2099 年的 E2E 测试周期。
- 运行数据（周记录、周报包）会通过本机服务保存到 `data/runtime-state/`，刷新页面后调查对话和周报阶段仍可恢复。
- 问题卡片的回答会保留在卡片内；模型会基于目标指标、历史、门店背景和前轮对话继续追问，不显示轮次编号。
- 模型返回的因果结论增加了事实 grounding 检查；无法在证据或运营回答中找到支撑词时，自动回退为编辑式、带边界的结论，避免把模型臆测写进周报。
- 复盘分析按 1/3、2/3、3/3 显示进度；经验与动作没有满足证据门槛时会明确显示“本周没有满足条件的候选”，不会生成空卡片。
- 门店上下文已隔离。东坝的经营事实不会再自动显示到中影；分别保存后切换门店可复核。
- 经营地图的长期机会、打法和验证状态刷新后仍可恢复；项目档案的门店选择器由服务端档案动态生成，并保留“新增门店模板”入口。
- 人工补充经验、人工补充动作、生成完整周报、复制完整周报和最后润色均已通过页面操作验证。
- 复制按钮会复制当前门店的完整周报正文，不再误报“请先生成周报”。

## 本次修复的关键问题

1. 页面初始化时运行时持久化桥接作用域错误，导致刷新时报 `workbench is not defined`；已修复为安全的运行时桥接，并将工作台状态纳入本地服务端运行态，避免阻塞页面。
2. 周报选择器保留未来 E2E 周期；已改为按当前日期过滤默认选择。
3. 因果结论可能出现未在运营回答中出现的泛化原因；已增加 grounding 校验并细化优惠券/活动判断。
4. 门店拆分后的复盘分析通过旧兼容层生成时可能丢失门店分析；已改为直接对门店周报包执行复盘分析。
5. 旧版事件监听器会与门店周报包监听器重复触发，造成“生成成功后又提示失败”；已增加事件拦截和包级按钮处理。
6. 人工补充动作在门店周报包中无效；已补齐新增、删除、勾选和保存逻辑。

## 仍需关注

- 外部模型的单次调用延迟较高；一次复盘分析需要三次串行调用，当前实测约 1 分钟以上。页面已有阶段提示，但还没有后台任务、取消或重试队列。
- 当前本地服务使用文件运行时状态；线上 EdgeOne 若要实现同样的跨设备持久化，需要把这层替换为 EdgeOne Blob，并补充部署侧绑定配置。本次未上线验证。
- 经营地图的机会/打法/验证等工作台状态现在会保存到本地服务端 `data/runtime-state/workbench.json`；线上跨设备持久化仍需下一阶段接入 EdgeOne Blob。
- 模型可能因证据不足返回空的经验/动作候选，这符合当前“没有可靠证据就不沉淀”的规则；如运营希望每周必有动作，需要另设人工动作模板策略。
- 当前 DeepSeek 配置是服务端代理模式；浏览器不保存或回显 API Key。若要使用真正的本地模型地址，需要在“总设置”中改服务端配置后再做一次 API 回归。
