# 溪语工作/生活联动实施与回归记录

日期：2026-09-04  
状态：本地完成，未部署线上

## 业务验收标准

1. 生活聊天不读取企业资料，也不向工作台回流。
2. 工作聊天能使用对应项目和门店资料，但保持溪语既有人格，不变成报告机器人。
3. 混合聊天只把工作片段送入企业链路，私人内容不进入企业候选，企业内容不进入私人长期记忆。
4. 已发生事实、运营判断、因果假设、进行中验证和正式经验必须分开表达。
5. 对话新知先进入候选箱，人工选择落点后才进入对应模块；经验不能越过验证直接成为正式可调用经验。
6. 重复、拒绝和冲突有程序级处理；服务故障时不能伪装已经读取资料。

## 已执行回归

| 场景 | 结果 | 关键观察 |
|---|---|---|
| 纯生活对话与退出工作语境 | 通过 | “先不聊工作”识别为生活对话，调用 0 条经营资料。 |
| 混合对话 | 通过 | 页面显示混合对话及记忆分流；工作事实回流候选，私人部分未进入企业候选。 |
| 已确认事实与因果边界 | 通过 | 能回答“科技馆客流明显回落是已记录事实”，同时说明其导致门店客流下降仍不能确认。 |
| 未闭合问题续问 | 通过 | 只追问一个最关键缺口：科技馆进入商场后实际到店的客流占比/同期变化。 |
| 工作台不可用 | 通过 | 页面仍可聊天，显示调用 0 条资料，并明确“拿不到工作台资料，暂时无法核对”。 |
| 候选语义重复 | 通过 | 同义改写合并到既有候选，不重复创建。 |
| 候选相反表述 | 通过 | “客流上升 20%”和“客流下降 20%”分别保留并进入冲突状态。 |
| 拒绝抑制 | 通过 | 与已拒绝候选同义的再次输入返回 suppressed，不重新制造待确认卡片。 |
| 候选应用 | 通过 | 人工选择目标后进入 linked；打法生成草稿，经验生成不可检索的待审核候选。 |
| 经营事件 API | 通过 | 创建、查询 pending、更新 delivered 和恢复测试状态均成功。 |
| 项目/门店权限 | 通过 | 授权门店返回 200，越权门店和未知用户返回 403；审计不保存聊天正文。 |

## 当前保留限制

1. 主动经营提醒默认关闭。接口和回执链已完成，但在确认真实账号映射、发送频率和免打扰策略前不应启用。
2. 当前权限文件是轻量 JSON 方案，适合现有免费服务器和少量账号；未来多组织、多角色时应换成正式权限表。
3. 语义去重仍是轻量文本算法，能处理常见改写和相反方向，但复杂隐含矛盾仍需要人工在“有冲突”列表处理。
4. 工作台单页前端较大，现有能力可用，但继续增加联动展示前建议拆分前端模块，降低回归风险。
