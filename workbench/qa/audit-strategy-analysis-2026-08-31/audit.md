# 经营地图·经营分析应用审计（2026-08-31）

## 审计目标

从运营管理人员的真实使用视角，判断当前模块能否做到：

1. 发现值得管理者关注的问题与机会；
2. 给出有本店数据依据、因果边界清楚的判断；
3. 引用可追溯、业务相似的外部案例；
4. 把机会转成低成本、可验证、可复用的经营动作。

## 页面入口证据

![经营地图入口](./01-strategy-map-entry.png)

入口已经按“需求获取 → 到店/进店 → 首次成交 → 内容/体验 → 客单/次卡 → 用户资产 → 复购/转介绍”组织经营链路。结构比单纯罗列指标更接近经营者思维，但当前各节点后端事实包仍未形成完整漏斗。

## 本轮已做事项

- 通过线上工作台真实触发外部模型节点分析，确认“运行专家分析”确实调用配置的外部模型，而不是前端写死结果。
- 核对了前端事实包、后端提示词、输出校验、知识库、项目档案、周报和经营事实关联路径。
- 调研东坝、中影两店场域，并更新本地及线上项目档案。
- 核对同行案例是否真的进入 AI 检索和输出证据链。

## 真实运行观察

一次线上节点分析输出了两个代表性结果：

1. **问题判断较好**：识别“销售票数连续三周下行且目标完成率不足五成”，同时引用本周、上周、近 4 周和近 3 周趋势。它可以回答“问题有多大、是否持续”。
2. **机会判断较弱**：输出“暑期尾声是转向本地家庭客群和低成本获客的窗口”，但只引用销售票数和日历常识，没有本店家庭客群占比、获客来源、历史转化，也没有可追溯案例。它实际上是一个待验证假设，却被包装成了机会。

这说明当前模块已经具备**趋势异常检测 + AI 文本审查**，但还不是完整的“有证据的机会发现引擎”。

## 核心应用问题

### P0：结论可能直接被带偏

1. **门店画像与隐藏标签不一致**：线上项目档案已纠正东坝和中影，但静态策略知识仍给东坝保留科技馆客群标签。打法排序仍可能继续把东坝往科技馆方向带。
2. **拆店后的新周报没有真正进入经营地图**：最新结构写在 `reportPackage.venueReports[venue].analysis`，经营地图仍主要读取旧的 `report.analysis`。运营已经完成的单店因果调查、结论和经验可能根本没被 AI 看见。
3. **没有真实同行案例 RAG**：知识库中的“行业案例”目前只是名称，没有案例主体、来源 URL、时间、做法、结果、适用边界。现有外部检索还是 GitHub 技术搜索，无法支撑经营机会判断。

### P1：能发现涨跌，但难做针对性判断

1. “全部门店”使用汇总指标，却只带通用项目画像，不会合并两店差异。
2. 提示词要求比较相邻漏斗，实际 payload 没有相邻节点数值和转化率。
3. 经营事实、验证、历史经验缺少严格的门店和时间过滤，存在跨店、未来信息污染风险。
4. 候选信号共用 5%、10%、15%、70% 等通用阈值，没有考虑金额影响、样本量、营业天数、季节阶段和指标波动性。
5. AI 能引用 `metric.current` 之类内部编号，但拿不到飞书表、sheet 和行列范围，运营无法追溯原数。
6. 验证结果仍以自由文本和人工状态为主，缺基线、样本、成本、对照、保护指标，无法沉淀成可信的内部成功案例。

## 两店画像校正

### 东坝店

应定位为“东坝万达三层、社区型商业综合体内的沉浸娱乐店”，重点分析：

- 商场内经过 → 驻足 → 咨询 → 付费的场内转化；
- 亲子、朋友/情侣、社区、学校和企业团体的来源差异；
- 相邻亲子与体验业态既是竞争，也可能是联票和互荐伙伴；
- 工作日闲时利用、商场活动、内容换新和本地社区触达。

### 中影店

应定位为“党史展览馆配套文化商业 + 中影影院 + XR体验的复合场域”，重点拆开四条来源：

- 科技馆亲子出馆；
- 党史馆个人/研学团体；
- 影院、电影 IP、市集与赛事直播；
- 亚奥赛演展外溢。

“附近有客流”不能直接成为因果。需要来源码、时段、活动日历和进店漏斗证明客流是否真正进入门店。

## 建议的机会证据链

每条机会必须按同一顺序生成：

`本店异常/趋势 → 门店经营事实 → 场域与人群适配 → 相似案例 → 小规模验证`

机会卡必须包含：

- 影响规模与目标指标；
- 受影响客群、时段和场景；
- 机制链与反证边界；
- 证据等级、原始数据来源；
- 外部案例来源、相似点和不可照搬差异；
- 执行前提、成本/难度；
- 测试动作、成功指标、停止条件、负责人和复盘日期。

## 当前维度缺口

除现有周度经营数外，至少要补八类：

1. 漏斗：场域客流、门前经过、驻足、咨询、下单、体验、复购/推荐；
2. 客群：亲子、结伴、散客、团体、新客、老客；
3. 商品内容：主题、票型、价格、时长、年龄限制、内容生命周期；
4. 时间事件：小时、工作日/周末、假期、天气、商场/影院/场馆活动；
5. 产能：设备、并发、场次、上座率、等待、故障、人员班次；
6. 渠道质量：金额、票数、佣金、核销、到店率、复购，而不是只看销售额；
7. 单位经济：客单、每体验者收入、毛利、获客成本、优惠侵蚀；
8. 本地生态：合作商户、场馆、学校、社区、竞品和联动效果。

## 优先级建议

1. **先修数据断链**：隐藏门店标签、拆店周报读取、门店/时间过滤、相邻漏斗。
2. **再建案例证据层**：案例必须可追溯、可比、可说明适用边界。
3. **再扩项目档案维度**：把地址、场域、经营节奏、活动日历、容量、产品和来源置信度结构化。
4. **最后优化页面表达**：只有证据链通过的内容才显示为“机会”；证据不足统一显示为“待验证假设”。

## 审计边界

- 页面入口截图已完成并验收。
- 外部模型调用链已通过真实页面操作验证一次；后续多节点浏览器操作受到当前自动化连接不稳定影响，因此不把该限制误报成产品 Bug。
